# ATK 会话泳道与异常定位设计

2026-11-06 · 提案，供实现与验收使用

打开 `atk visualize trace` 后，调查者应当能先看清一次采集里各条 Trace 的先后、重叠和空档，再从已记录的问题跳到具体节点及其证据字段。页面以已有归档为输入，继续生成一个只读的离线 HTML。

## 首屏与阅读顺序

默认打开「执行流程」。顶部沿用 ATK 品牌栏、会话 ID 和来源，显示当前快照选择器、采集范围、Trace 数、observation 数与本快照关联的问题数。采集完整性与检测覆盖分别呈现。若有多份采集，默认选最新一份，标明采集时间和状态。遇到损坏快照时展示错误及可切换的其他快照。

| 区域 | 首屏呈现 | 交互结果 |
| --- | --- | --- |
| 会话泳道 | 一个快照共用一根横向相对时间轴，每条 Trace 一行，按首个可信时间排序。左侧显示名称、短 ID、节点数，右侧画出范围和事件分布 | 展开某行可看 Agent、模型、工具及其他操作的实际分布。「聚焦此 Trace」放大该段时间，「全会话」恢复原尺度 |
| 已记录异常 | 桌面在图旁显示问题 ID、简短现象及证据位置数。按问题去重，同一问题可涉及多条 Trace。小屏排在图下 | 点问题可逐条选择证据，定位到图中并打开字段。点节点可反查所有引用它的问题 |
| 节点列表与详情 | 图下沿用可搜索、筛选和分页的列表，与泳道共享选择。右侧沿用现有详情抽屉 | 图、列表、证据链接可打开同一节点。优先展示命中的字段，再查看完整预览、输入输出和原生父子关系 |
| 异常与会话概览 | 保留完整异常列表、问题／诊断／修改／验证四阶段和会话元数据 | 项目上下文、全部快照、检测范围与缺口仍可查阅。其他快照的问题可从会话异常列表进入 |

**一次典型调查。** 用户点一个“重试缺少前文”的问题，在证据列表分别选择前一条 Trace 的输出和后一条 Trace 的模型输入。页面依次定位到两份原始引用，显示对应字段，可返回上一位置继续比较。两段之间保留真实时间空档。若引用只指向整条 Trace 的输入，定位到 Trace 标题及该字段。界面仅在存在关联记录时表述两次执行的业务关系。

## 泳道如何表达执行

借鉴 MCS 的共用时间尺、可折叠泳道、事件刻痕与详情联动。MCS 从日志中的 Agent/Task 调用划分主线程和子代理，ATK 面向多来源、多 Trace 的会话，以稳定的 Trace 标识作为第一层。Trace 行表示已知观测范围。一次用户回合与多条 Trace 的关系仅在原始材料有标识时显示。

- **区间、点与空档。** 起止时间有效且结束晚于开始时绘制区间条。起止相同画点并显示“持续 0”；仅有开始时间画发生点，详情标“无结束时间”。Trace 概览的范围用细线或包络表示，节点的实际运行区间用实条表示。横轴默认按真实经过时间绘制，详情补充带时区的绝对时间。保留相邻 Trace 间的空白，避免把观测跨度读成累计执行耗时。
- **层级与并行。** 展开后按快照已有类型归组，例如 Agent、模型、工具、事件、其他跨度，仅显示有数据的组。原生父子链在选中节点时高亮，父节点须能在同一快照、同一 Trace 中唯一解析。同类重叠区间上下错开。角色行只说明节点类型，运行线程或子任务须有显式身份才标注。缺父、重号或循环保留原节点，并提示关系无法解析。
- **长会话。** 收起时按当前像素范围合并密集刻痕，显示数量和问题标记。点一簇可看全部成员或缩放到局部。问题证据在聚合层始终有入口。搜索命中折叠组时显示命中数；点结果展开并定位。节点总数按归档 observation 口径计算，Trace 外壳和附件单列。
- **资料有限时。** 异常时间、无时间、无 Trace 归属和仅有文本的证据都可从相应列表进入。JSONL 可用原始行号导航；无可用时间时按来源分组、依原始顺序展示，并标明“没有可用时间轴”。时间顺序无法证明因果。缺少检测记录显示“尚未检查”，已检查但零问题显示检查范围和已知缺口。

## 异常如何落到证据

归档里有三种含义不同的信号，统一用形状和文字区分。橙色强调当前选择。问题带旗标和 ISSUE ID，运行时显式错误用带感叹号的标记，材料或引用缺失用虚线和文字说明。问题旗标意为“此处有该问题的证据”，因此正常的用户输入也可以带旗标。错误节点、无输出节点均保留其原始语义；业务问题数仅取自已保存的 issue。

1. 从每个问题当前版本的 `evidence` 建立反向索引。校验引用的快照、相对路径、SHA-256 与 JSON Pointer 或行号。精确命中节点时直接定位；指向嵌套字段时，在同文件同摘要内按解码后的 Pointer 路径段寻找最近的已知节点祖先。比如 `/trace/observations/10/output/text` 归属第 10 项，不能误命中第 1 项。仍须打开原始的 `output/text` 引用。
2. 整条 Trace 的输入输出落在 Trace 行。只绑定文件、行或处理记录的引用保留其实际层级。哈希不符、目标缺失或不能唯一确定时，显示“证据不可定位”及原因。诊断、修改、验证产生的材料留在各自阶段，避免混进原会话的时间线。
3. 同一问题可标记多处证据；同一节点可列多个问题。同一证据在多个入口共享一处详情。跨快照跳转切回证据最初绑定的快照，同时展开所属行，暂时让目标对当前筛选可见。返回时恢复之前的快照、筛选、时间范围与键盘焦点。重新采集相同的 Trace ID 可生成新的归档位置，旧旗标只跟随原引用。

## 实现范围

| 位置 | 拟议改动 |

| [节点读取](../agent_tune_kit/traces/query.py) | 复用已有时间、类型、原生 ID 与证据引用。按需从保留材料投影原生运行级别等少量字段，兼容没有这些字段的旧输入 |
| [展示数据](../agent_tune_kit/visualize/trace.py) | 沿用逐快照校验和单文件生成。构建一次性的轻量节点、时间和问题位置索引，以现有节点序号或引用为键，避免再次序列化大段输入输出 |
| [页面与样式](../agent_tune_kit/visualize/assets/trace/page.html) | 复用浅灰底、白色面板、橙色选中态、原有字号、标签和抽屉。泳道优先使用现有原生 HTML、CSS 与少量 SVG 图元。控件可用键盘操作，按 Escape 关闭详情并恢复焦点。窄屏保留可横向滚动的图和等价列表 |
| [前端交互](../agent_tune_kit/visualize/assets/trace/app.js) | 由同一组状态驱动图、列表和详情。先渲染 Trace 行和当前窗口内的标记，按需展开。保持现有 CSP、JSON 安全嵌入与正文文本渲染 |

沿用现有命令、归档结构、离线打开方式和输出覆盖保护。预览只读归档，泳道和反向索引是页面内的派生数据。首版交付范围为全会话视图、局部聚焦、异常双向定位和列表回退；跨快照对比、成本统计和自动诊断另行评估。

## 实施顺序与验收

1. **先验证“看清流程”。** 用当前授权的私有会话在本地生成候选预览。按已归档观测计数，3 条 Trace、450 个 observation 均可追溯；其中 84 个为正时长区间、25 个为零时长、341 个只有开始时间。密集行展开后覆盖全部成员；两条 Trace 间约六分钟的空档在全局尺度可见。私有正文与生成页面仅在本地验收，自动化夹具使用合成数据。
2. **再验证“找到问题”。** 从真实归档的 3 个问题各选择一个证据，从问题到原始字段仅需「选问题 → 选证据」；从节点可返回问题及处理记录。5 个原生 ERROR 与 3 个已记录问题分别计数。用合成的两次采集检验跨快照、同一节点多问题、深层字段、文件级证据、行号与失效引用。
3. **最后验证可读性与兼容性。** 对同一份归档比较现有与候选的文件大小、首次可操作时间、展开密集 Trace 和点击证据的响应。首次绘图只依赖当前快照的轻量索引，避免在点击时扫描全部正文。桌面及窄屏在断网下完成一次问题调查，并用键盘返回列表。覆盖仅采集、零问题、部分覆盖、未定时和损坏材料；生成前后核对归档摘要，并复跑现有预览测试。

数值来自 2026-11-06 对一份授权本地归档的只读核对，仅作为该样本的验收预期。正式页面展示当前快照实际计算的数值。
