# ATK 会话轨迹可视化：Session · Trace · Issue 片段

2026-11-08 · 产品与实现约定。使用方法见[轨迹调优指南](trace-tuning.md)；浏览器实测见[验收记录](trace-tuning-validation.md)。

## 产品核心

轨迹持续调优的核心不是“轨迹浏览器附带问题列表”，而是：

1. 用**完整执行轨迹**呈现会话的执行链路（Session → 多条 Trace → 事件）。
2. 用**Issue**定位问题，并用 Issue 关联到的**轨迹片段**圈定精确范围。
3. 围绕 Issue 呈现诊断、修正建议、改动与验证。

关联关系由分析方在检测时写入 Issue 记录；页面只负责呈现，不猜测范围。

| 关系 | 怎么成立 | 页面怎么呈现 |
| --- | --- | --- |
| Session 下有多条 Trace | 归档按原生 Trace ID 保存 | 上方泳道每条 Trace 一行，共用会话时间轴 |
| 一条 Trace 关联多个 Issue | 各 Issue 的片段落在同一 Trace | 行头圆标显示关联问题数；选中问题后该 Trace 行叠加片段色带 |
| 一个 Issue 关联多条 Trace | Issue 内写多个分属不同 Trace 的片段 | 问题栏列出片段；选中后各 Trace 行分别叠色带 |
| Issue 关联轨迹上的一段范围 | Issue.`segments[].scope`（`node` 或 `from`/`to`） | 事件列表按片段分组；证据字段在详情中高亮 |
| 诊断 / 修正 / 验证与 Issue 关联 | 仍挂在 `issues/<id>/` 下；正文可用 `ISSUE-001/S2` 引用片段 | 问题详情抽屉按阶段展开；片段引用可点击定位 |

## 页面布局

页面将单条执行观测统一称为“事件”，适用于泳道、列表、详情、统计和筛选；原始类型与归档字段名保持不变。聚合刻痕表示因时间轴位置接近而合并展示的多条事件；点击后复用下方事件列表，不另设事件名称按钮区。

默认打开即完整会话。布局从上到下、从左到右：

```text
┌ ATK · 会话 <id> · N Trace · M 事件 · K 问题                                     ┐
├ 问题栏（可收起） ┬ 执行链路 ─────────────────────────────────────────────────────┤
│ 搜索 · 状态筛选 │            0:00        2:38                 8:46     10:15    │
│                 │ T1 · e8a3      ━                                              │
│ ISSUE-001 已诊断│ T2 · 2a7a  ②     ├━━━━━━━▓▓━━━━┤                              │
│  最后模型迭代…  │ T3 · f4db  ①                                  ├━━━━━━┤        │
│  T2 · 1:38.600  │──────────────────────────────────────────────────────────────│
│ ISSUE-002 待处理│ 问题片段 · 共 2 段 [查看完整上下文] [退出问题定位]              │
│                 │ 事件 · 片段内 6 条 · 已折叠 120 条 [全部类型▾] [搜索]       │
│  2 段 · T2 T3   │┃最后一次模型迭代…                           2 条事件 · 16s   │
│ ISSUE-003 …     │┃01:38.6 T2  llm.call                   ★ input·output        │
└─────────────────┴──────────────────────────────────────────────────────────────┘
                                      点事件 /「详情」时右侧覆盖式抽屉 ──▶ ┃详情┃
```

桌面端工作区使用页头和提示区之外的剩余视口高度。问题筛选、会话概要、事件筛选与表头保持可见，问题列表和事件列表分别滚动，内容长度互不影响；短列表保持自然行高，不补空行。退出问题或事件聚焦时恢复问题栏与事件列表各自的滚动位置。

窗口较窄或高度过低时切回上下排列与页面滚动，避免固定工作区挤掉事件列表。泳道可手动收起；较矮的桌面窗口默认收起泳道，手动选择在当前页面内保留。

### 上方：简洁泳道图

- 每条 Trace 一行：执行范围条、事件刻痕、行头（序号、短 ID、事件数）。
- **默认不加问题轨、不吸附常驻 Issue 色带。** 行头只放一个小圆标，数字表示关联了几个问题；点击圆标在问题栏筛出这些问题。
- 选中某个 Issue 后，该 Issue 的片段以半透明色带**叠在所在 Trace 的那一行上**，不新增泳道行；当前片段颜色加深。
- 悬停问题栏条目时，泳道临时预览该问题的片段；移开即消失。
- 点行头定位该 Trace 首条事件；点单条事件刻痕定位并打开对应事件；点聚合刻痕只聚焦列表，点击具体事件行才打开详情。多 Trace 共用会话时间轴；并发事件出现在不同行的同一横坐标。
- “聚焦”同时只看单条 Trace 的泳道与事件，并将时间轴适配到该 Trace 的范围；“定位”保留查看范围，跳到对应事件。
- 聚焦后，泳道上方标题显示“聚焦 T2 ▾”，可直接切换 Trace；旁边的“返回完整会话”恢复聚焦前的筛选、选中事件和滚动位置。完整会话与单 Trace 会话不显示切换和返回控件。
- 泳道过高时区内滚动；互相遮挡的刻痕才合并，同处每条事件都可定位。无时间的事件列在所属 Trace 的“时间未知”下。有明确派发身份的子任务可在单 Trace 聚焦后展开。

### 下方：事件列表

- 底部显示当前可见事件范围及筛选后的总数，区分“向下滚动查看更多”“已到列表末尾”和短列表的“已显示全部”。片段内仍有折叠上下文时提示可展开，不将其描述为全部事件已经展示。提示随滚动、筛选和窗口大小更新，片段标题和折叠项不计作事件。

- 默认按会话时间连续列出全部事件。被任意 Issue 引用的行，末尾显示窄标签（如 `001`），不单独占列。
- 点击聚合刻痕后，列表只展示该刻痕包含的事件，标题显示所属 Trace、所选时段和事件数；无时间事件显示“时间未知”。列表仍可搜索和筛选，计数显示命中数与组内总数。所选事件集合固定，窗口缩放不会改变成员。
- “返回全部”恢复进入前的选中事件、滚动位置和筛选；原先有筛选时标为“返回筛选结果”，从问题定位进入时标为“返回问题片段”或“返回问题上下文”。连续点击另一聚合刻痕只替换当前集合，返回目标保持不变。切换 Trace 或快照清除该集合。
- 聚焦 Trace 后标题显示“事件 · T2”及当前事件数。事件工具栏仅保留事件范围、类型和搜索，只筛选列表；Trace 切换位于泳道上方。
- 选中 Issue 后：
  - 恢复完整会话范围，呈现跨 Trace 的所有问题片段；退出问题定位后恢复原来的 Trace 聚焦状态。
  - 范围内行加左侧色条，并插入段头行，显示片段摘要、事件数和时长。
  - 证据节点用 ★ 标出被引用的字段名。
  - 自动聚焦该问题的所有片段，其他事件折叠为“⋯ 展开这 N 条上下文事件 · 跨度 Xm Ys ⋯”，可局部展开；并发 Trace 交错的事件也完整保留。
  - 导航栏说明当前问题、片段数量和位置；计数分别展示片段内、已折叠和额外展开的上下文事件数。
  - “查看完整上下文”展开全部事件并保留问题高亮；“返回问题片段”重新折叠上下文。“退出问题定位”恢复进入前的筛选条件和滚动位置。
- 跨 Trace 的片段按时间先后排列，中间空档保留为折叠行。
- 筛选、搜索、类型过滤、分批渲染保留。搜索命中或当前片段落在折叠组时直接展开目标。

### 左侧：常驻问题栏

- 默认约 260px；点 « 收成约 40px 窄条（只显示编号与状态点），把宽度让给泳道。收起状态本地记住。
- 每张卡片显示问题编号、实际进度、分类标签（有分类时）、标题和按开始时间排列的片段。每段先显示摘要，下方显示 Trace 和开始时间。开始时间与泳道共用计时起点，固定片段 ID 在详情中显示。
- 实际进度与项目大盘共用同一套口径，由诊断、改动和最近一次验证结论计算，不读声明的 `status`（`excluded` 除外）。标签依次为待诊断、已诊断、修复中、待验证、验证中、验证失败、无法判断、验证通过、已排除；规则见 [trace-tuning.md](trace-tuning.md) 的“Actual progress”。
- 点问题标题或“定位”：选中该问题并定位首个片段。点片段：定位该段。卡片上的“详情”打开问题详情抽屉。
- 旧问题没有明确范围时提示“该问题尚未圈定片段”，定位已有证据节点或打开归档引用；没有可定位内容时展示问题详情。
- 顶部提供搜索和实际进度筛选。顶层不再设“问题列表”Tab 和“定位问题”下拉。

### 右侧：覆盖式抽屉（非模态）

抽屉覆盖在内容上方，**不挤压布局**，开关都不改变泳道宽度。无遮罩，背后的泳道与列表仍可操作；宽度可拖，默认约 480px。窄屏默认从底部打开，若会遮住点击的事件行，则移到顶部。

**事件详情**（点任意行或刻痕）：

- 头部只保留事件名称与关闭按钮。时间、Trace、类型、问题标记和结果摘要由列表承载；抽屉不再重复这些信息，也不展示父链、调用关联、节点元数据、原始 JSON 或常驻搜索。
- 正文只展示默认展开的输入、输出，并分别提供复制按钮。文本保留原文，对象和数组使用缩进 JSON；长内容在内容区滚动查看，不裁剪字段。缺失值与空文本明确区分，`false`、`0`、`[]`、`{}` 正常展示。
- 从证据入口打开时，在输入或输出原文中定位、高亮被引用字段，不另建重复的字段预览。输入输出之外的引用或无法映射到原文的证据才单独展示，并保留预览截断、不可读取提示及返回问题的入口。
- 抽屉开着时 `↑/↓` 逐条切换事件，列表与泳道选中态同步，便于人工确认。

**问题详情**（从问题栏打开）：

- 顺序：描述与片段 → 诊断 → 修正 / 改动 → 验证。
- 正文中的 `ISSUE-001/S2` 是可点击链接，点击后主区定位该片段，抽屉保持打开。
- 从问题证据进入事件后可返回原问题；问题入口保留在问题栏与片段导航中。

### 导航与状态

- URL hash 深链：`#issue=ISSUE-001&seg=S1`、`#event=<trace>/<node_id>`。
- 默认 `preview.html` 旁存在项目大盘 `../index.html` 时，顶栏显示“← 大盘”，回到大盘并打开本会话的抽屉；分类标签跳到大盘的对应分类。大盘本身见 [trace-dashboard-design.md](trace-dashboard-design.md)。
- `Esc` 依次关闭抽屉、退出聚合事件聚焦、退出问题定位，并恢复进入相应视图前的位置与筛选。
- 页面保持离线只读；人工确认结论可结合复制的输入输出反馈给 Agent，由 Agent 写回记录，归档中的精确引用保持不变。

## 片段契约（分析方写入，页面只呈现）

片段不是独立实体，写在 Issue 记录的 `segments` 里，随 Issue 创建与修订。固定 `role` 分类不做；每段用自由文本 `summary` 说明作用。完整字段与 CLI 校验见 [trace-tuning.md](trace-tuning.md) 的“Issue 片段”。

| 范围写法 | 含义 | 典型用途 |
| --- | --- | --- |
| `{"node": ref}` | 一个执行单元及其子孙 | `agent.iteration #24` 及其内的 `llm.call` |
| `{"from": ref, "to": ref}` | 同一 Trace 内按时间连续的一段 | 从 `sdk.result` 到对应的 `frontend.ai_message` |

规则摘要：

- 端点必须属于同一 Trace；`from` 不晚于 `to`。
- 片段 `evidence` 必须落在范围内，或为范围内节点的祖先 / 该 Trace 根（用于父链归属与 Trace 级上下文，不拉长片段）。
- CLI 分配 Issue 内稳定的 `S1`、`S2`…；`--dry-run` 回报每段覆盖的节点数与时长，不设硬性阈值。
- 一个 Issue 跨多 Trace → 多个片段；两个 Issue 圈到同一段 → 各存各的，页面显示重叠。
- 旧 Issue 没有 `segments` 时，只把证据显示为单点并标“未圈定范围”；**页面不再用启发式猜范围**。

## 实施顺序与验收

| 顺序 | 改动 | 核验 |
| --- | --- | --- |
| 1. 契约与 CLI | `segments` 校验 / 解析 / `--dry-run`；`overview` 按 Trace 与时间排序；删除启发式片段推导 | 单元测试覆盖合法 / 跨 Trace / 祖先证据 / 旧数据；dry-run 节点数与样本一致 |
| 2. Skills 与文档 | detect / diagnose / optimize / verify；本页与 trace-tuning | Skill 包校验通过；README 只同步使用者可见变化 |
| 3. 页面 | 问题栏 + 简洁泳道 + 事件分段 + 覆盖式抽屉 + 深链 | Magic 样本：默认可读完整会话；选中问题后色带与段头正确；事件抽屉可逐条确认；窄屏底部抽屉可用 |
| 4. 样本改写 | 带修订号把 3 个 Issue 写成带片段的版本（Magic `.atk/`） | 再生预览后 3 个问题均可按片段定位；归档 digest 与写回一致 |

验收重点：用户能否在不打开原始 JSON 的情况下复述一次执行，并通过一个问题精确落到分析方圈定的范围，再在抽屉中核对证据字段。
