# ATK 执行轨迹与异常片段设计

2026-11-06 · 页面设计与实现约定。当前版本的操作方式和浏览器实测分别见[轨迹使用指南](trace-tuning.md)和[验收记录](trace-tuning-validation.md)。

## 打开时就能读完整会话

默认范围是**当前会话的全部 Trace、全部已采集记录、完整时间轴**。打开页面就能从第一条动作向下读到最后一条。上方泳道回答“每条 Trace 在哪段时间执行”，下方列表回答“当时依次做了什么”。选择异常后，两处共同定位到相关片段。只有点“只看此 Trace”或主动筛选才缩小阅读范围。

参考 MCS，把动作标在所属执行线上，并按时间列出记录。事件、跨度、模型、工具和 Agent 作为行内类型或可选筛选条件。沿用 ATK 的浅色背景、字体和橙色选中态。点开详情可查看输入输出、原始字段和诊断记录。

## 单 Trace、多 Trace 与空间不足

| 场景 | 泳道 | 执行列表 |
| --- | --- | --- |
| 会话只有一条 Trace | 直接用整幅时间轴展开这条 Trace 的主执行线。有明确派发和身份的子任务可在其下展开 | 从头列出全部动作，省去 Trace 选择器和重复的 Trace 列 |
| 会话有多条 Trace | 每条 Trace 一行，共用会话时间轴，按首次观测排序。并发动作出现在不同行的同一横坐标，前后执行之间保留真实空档 | 所有 Trace 的动作按会话时间混排，行内标明所属 Trace。连续阅读自然跨过 Trace 边界，并发动作保留各自归属 |
| 泳道行数过多或某条 Trace 太密 | 行头和时间刻度固定。泳道自然高度超过可用视口约三分之一时，区内滚动浏览全部 Trace。短条可点整行。只有相互遮挡的动作刻痕合并，同处的每条记录都可定位 | 全会话列表继续滚动可读。需要细看时点“只看此 Trace”，复用单 Trace 布局放大这一条，保留会话相对时间。“返回完整会话”恢复原来的 Trace 行和列表位置 |

例如样本中的 T1 观测范围约 6.4 秒，T2 在约 119 秒内有 370 个观测。在 1,000 像素宽的整段会话时间轴上，它们分别只占约 10 和 193 像素。因此序号、短 ID 和可点击行头独立于条形宽度，局部细读按 Trace 放大。列表较长时分批渲染可见行，搜索、计数和异常定位始终覆盖完整会话。

条形覆盖首末可定位记录，刻痕表示实际动作。普通 AGENT 或 SPAN 的父子关系不足以证明独立子任务。无时间的观测列在所属 Trace 的“时间未知”下，整条 Trace 均无时间时仍保留可打开的行头。同时间记录用稳定的 Trace 顺序和原始序号排序。

默认列表给每个观测一行，显示时间、动作名称和已有的简短结果。调用与返回有已验证的关联时，可从一行跳到另一行。用户可以主动切到“关键动作”收起重复环境读取、心跳等辅助活动。搜索命中或异常引用落在折叠组时，直接显示目标记录。

## 异常怎样指向一段执行

**用户看到的是片段，归档中仍以既有证据引用为依据。** 片段是预览生成时的导航范围。它表达用户阅读该问题时应查看的上下文。证据点所在的整段耗时不能直接解释为故障持续时间。

1. 复用已校验的当前 Trace、字段摘要及 Pointer／行号定位。节点内部多个字段引用同一动作时产生一个动作锚点，并在详情保留所有字段。Trace 根的输入、输出和元数据作为“本次执行的上下文”，不使用根的整个跨度扩大片段。
2. 先按 Trace 和已知子任务分开处理。优先取锚点所在的最近一个可识别的小执行单元，例如有原生关联的一次工具调用及结果，或一次模型迭代。若祖先只是贯穿全回合的执行壳，或资料不足，以锚点所在行为中心，最多各带前后两条关键动作，只使用距锚点 30 秒以内的实际记录，避免把长时间空档纳入阅读范围。这个窗口是界面补充的上下文，只有原引用带证据标识。
3. 在同一执行中合并重叠的上下文窗口。间隔较远的窗口分别编号。跨 Trace 的证据始终分段，保留中间空档。仅有 Trace 级证据时定位该执行并标“执行级证据”。仅有文件或无时间的行引用时直接进入对应记录。失效引用显示原因，不以相邻时间或其他快照同名节点代替。
4. 点击异常，把各个片段**分别标在所属 Trace 的行上**，选中首个可定位片段，滚动到其证据行并保留前后动作。在“只看此 Trace”或筛选状态收到跨 Trace 跳转时，临时显示目标所在的完整会话。用“上一片段／下一片段”切换，原始字段按需展开。退出异常定位即可回到进入前的范围、筛选、滚动位置和焦点。

**在样本里点 ISSUE-002。** T2 的初始化记录（会话时间约 00:43）和 T3 的重试初始化、模型调用（约 08:52–08:54）分别在两条泳道上被标出。切到 T3 的模型调用即可核对 `input/messages` 和输出，Trace 根元数据在本 Trace 的上下文中可查。T2 结束到 T3 开始相隔 6 分 8 秒，这段空档保持空白。

## 实施与验收

| 顺序 | 改动 | 用真实或合成材料核验 |
| --- | --- | --- |
| 1. 默认完整会话 | 在现有 `lanes.js`、`page.html`、`styles.css` 实现共享时间轴和逐 Trace 行。`app.js` 统一记录顺序和范围，复用单 Trace 布局作局部放大 | Magic 样本初始即显示 3 条泳道。不点任何 Trace 或异常，仅滚动即可读到 33 + 370 + 47 个观测，按原标识逐项核对。合成单 Trace 直接展开，多 Trace 并发保持时间对齐。密集、超高及窄屏视图能从完整列表定位到末条 Trace 并返回 |
| 2. 增加异常片段导航 | 在现有 `visualize/trace.py` 的证据定位结果上计算片段，保存节点序号／引用键，避免复制正文。在 `app.js` 联动选区、记录和详情 | 本地 3 个问题、22 条引用逐一可追溯。单 Trace 内相距较远的证据不被涂成一个长故障区。跨 Trace 的重试问题可以分别阅读先前执行与重试输入，中间数分钟空档保留。同一节点多字段或多问题可追溯 |
| 3. 真实操作回归 | 复用单文件离线生成、已存快照、搜索及证据详情。补片段计算测试，更新真实浏览器回归 | 桌面与窄屏均能“点问题 → 看片段 → 切到下一段 → 回原位置”。连续点击普通动作时列表位移为 0。覆盖部分采集、零问题、无时间、历史快照及损坏引用 |

第一版可直接由现有归档派生，保持 `atk visualize trace` 命令、issue 存储及离线只读约束。先用一份候选预览验收阅读体验，重点看用户能否在不打开原始 JSON 的情况下复述一次执行，并通过一个问题找到相关的前后动作。
