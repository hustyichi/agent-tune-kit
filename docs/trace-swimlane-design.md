# ATK 执行轨迹与异常片段设计

2026-11-06 · 修订提案。本文定义下一版页面；当前可用版本及已验证行为见[轨迹使用指南](trace-tuning.md)。

## 用户如何阅读一次执行

首页先回答三个问题：这次会话经历了哪几段执行？选中的一段按顺序做了什么？某个已记录问题发生在哪一段上下文里？页面上方用紧凑泳道定位执行，下方的**时间顺序动作流**承担主要阅读工作。用户既可以从头阅读，也可以从异常直接进入相关片段。

参考的 MCS 实例包含 1,418 条事件、14 条泳道。主线程和有身份的子代理各占一行，工具调用等动作以刻痕落在对应执行线上，下面用可折叠、可搜索的记录解释动作内容。ATK 当前把同一 Trace 按事件、跨度、模型、工具、Agent 分层，再在每层堆放区间；用户需要自己把五行重新拼成一次执行。下一版删除这五组泳道和数字簇。

首屏保留必要的会话身份和快照选择，采集说明、来源及摘要收进「会话信息」。泳道可收起。异常入口标注当前快照关联的问题数，点击后列出 ID、简短标题和相关执行。大段问题描述、诊断、修改和验证按需打开。沿用 ATK 的浅色背景、字体和橙色选中态。动作流用紧凑文字行，右侧详情仅在需要查看输入输出时出现；窄屏上下排列。

## 泳道画什么

- **横轴为同一快照的真实经过时间。** 默认用“分:秒”，鼠标或键盘聚焦后可查看精确时间。顺序发生的多个 Trace 在一条标为“会话”的时间线上画为分开的执行段，按开始时刻编号。段条表示从首个到末个可定位记录的观测范围，两段之间保持留白。展示真实标题或安全的已有摘要；重名时用“执行 2 · 短 ID”区分。
- **纵向只区分确实独立的执行。** 有明确派发／父任务身份的子代理可展开为子泳道，用任务名称标记。普通 AGENT 或 SPAN 节点及其父子关系本身不足以证明独立子任务。同一时间重叠且无法确认关系的 Trace 分行标明各自身份。无时间记录仍可从所属执行的记录列表进入。
- **用少量刻痕标动作。** 只在有明确记录时标出请求、委派、关键工具调用和最终返回；密集刻痕合并显示，点击展示该处的动作列表。类型作为事件行的小标签或筛选条件。选中异常后，只在相关执行上显示片段括线和当前选区，避免默认满屏旗标。
- **这份会话的预期首屏。** 本地样本有 3 条顺序执行的 Trace，分别含 33、370、47 个观测。在没有独立子任务标识的情况下，首页只需一条会话线、三个可点击的执行段。即使选中最密集的中间一段，展开的也是它的动作记录。

## 动作流怎样读得懂

默认按时间正序显示“用户请求 → Agent 采取的动作 → 可观察结果”，每行显示相对时间、动作名称和一行可核对的摘要。有同一调用 ID 或可验证配对关系时，把调用和结果放在同一行；只有一侧则原样显示。缺少语义映射的来源直接用原生名称，避免从长提示或私有正文推测任务意图。原始记录顺序作为同时间的稳定次序，无法定时的材料单列并标明来源。

“关键动作”默认收起重复环境读取、心跳等已识别的辅助活动，同组显示条数并允许展开。“全部记录”可查看每个观测。即便某问题的唯一证据是通常会折叠的环境事件，从问题进入时也必须显示该记录。搜索命中时可展开所在位置。点击普通行仅更新选中态和详情，保留列表位置、泳道尺度和键盘焦点的返回目标。

## 异常怎样指向一段执行

**用户看到的是片段，归档中仍以既有证据引用为依据。** 片段是预览生成时的导航范围。它表达用户阅读该问题时应查看的上下文；证据点所在的整段耗时不能直接解释为故障持续时间。

1. 复用已校验的快照、文件摘要及 Pointer／行号定位。节点内部多个字段引用同一动作时产生一个动作锚点，并在详情保留所有字段。Trace 根的输入、输出和元数据作为“本次执行的上下文”，不使用根的整个跨度扩大片段。
2. 先按原快照、Trace 和已知子任务分开处理。优先取锚点所在的最近一个可识别的小执行单元，例如有原生关联的一次工具调用及结果，或一次模型迭代。若祖先只是贯穿全回合的执行壳，或资料不足，以锚点所在行为中心，各带前后两条关键动作。这个窗口是界面补充的上下文，只有原引用带证据标识。
3. 在同一执行中合并重叠的上下文窗口；间隔较远的窗口分别编号。跨 Trace 的证据始终分段，保留中间空档。仅有 Trace 级证据时定位该执行并标“执行级证据”；仅有文件或无时间的行引用时直接进入对应记录。失效引用显示原因，不以相邻时间或其他快照同名节点代替。
4. 点击问题立即选中第一个可定位片段，泳道突出该范围，动作流同步显示前因后果，命中行带标识。多个片段提供“上一段／下一段”和执行名称，允许展开上下文或返回全会话。仅在用户点“查看原始证据”时打开具体字段；从另一快照进入时明确切回原快照，返回恢复先前的范围、筛选、滚动和焦点。

## 实施与验收

| 顺序 | 改动 | 用真实或合成材料核验 |
| --- | --- | --- |
| 1. 简化基础视图 | 改造现有 `lanes.js`、`page.html`、`styles.css`，绘制执行段与有依据的子泳道。将 `app.js` 的扁平节点列表改成可折叠的时间顺序动作流 | 本地样本首屏可直接辨认三段执行及空档；选执行 2 后能顺序阅读动作。全部记录能找回 450 个观测。重名 Trace、并发子代理及未知类型用合成输入覆盖 |
| 2. 增加异常片段导航 | 在现有 `visualize/trace.py` 的证据定位结果上计算片段，保存节点序号／引用键，避免复制正文。在 `app.js` 联动选区、记录和详情 | 本地 3 个问题、22 条引用逐一可追溯。单 Trace 内相距较远的证据不被涂成一个长故障区；跨 Trace 的重试问题可以分别阅读先前执行与重试输入，中间数分钟空档保留；同一节点多字段或多问题可追溯 |
| 3. 真实操作回归 | 复用单文件离线生成、已存快照、搜索及证据详情；补片段计算测试，更新真实浏览器回归 | 桌面与窄屏均能“点问题 → 看片段 → 切到下一段 → 回原位置”。连续点击普通动作时列表位移为 0。覆盖部分采集、零问题、无时间、历史快照及损坏引用 |

第一版可直接由现有归档派生，保持 `atk visualize trace` 命令、issue 存储及离线只读约束。先用一份候选预览验收阅读体验，重点看用户能否在不打开原始 JSON 的情况下复述一次执行，并通过一个问题找到相关的前后动作。
