# Agent Tune Kit

简体中文 | [English](README.en.md)

[![PyPI](https://img.shields.io/pypi/v/agent-tune-kit.svg)](https://pypi.org/project/agent-tune-kit/)

**找出 Agent 为什么失败，验证每次修改是否真的有用。**

Agent Tune Kit（ATK）是一个本地 Codex 插件。你在 Codex 对话中提供 Agent 项目和测试任务，就可以评测当前表现、分析失败原因、尝试修改，并对比修改前后的结果。

适用于已有 Agent 的 Prompt、业务 Skill、代码或配置调优。无需把项目迁移到新的 Agent 框架。

[安装](#安装) · [快速开始](#快速开始完成第一次评测与改进) · [分析已有结果](#只有运行结果也可以开始) · [常见问题](#常见问题)

## 它能帮你解决什么问题

| 你的问题 | 用 ATK 可以做什么 |
| --- | --- |
| Agent 有时答错，但不知道从哪里改起 | 用代表性任务评测，结合输出和运行记录调查失败原因 |
| 改了 Prompt，几个例子变好了，其他任务呢？ | 对比修改前后表现，同时检查原本正常的任务有没有退化 |
| 试过很多修改，记不清哪些有效 | 保留每次修改的结果与采用理由，支持恢复到已记录的版本 |
| 已经有批量结果或 Langfuse 导出 | 直接导入分析，无需先接入 Agent 的运行方式 |

ATK 面向**已经能运行的 Agent，或已有的运行结果**。如果你还在从零搭建 Agent，先让它完成一项实际任务，再用 ATK 评测和改进。

## 它如何工作

```text
你的 Agent + 测试任务 → 评测现状 → 分析原因 → 尝试修改 → 对比验证 → 决定是否保留
```

ATK 把这条流程接在你现有的项目上，分工如下：

| 组成 | 负责什么 | 对你的价值 |
| --- | --- | --- |
| 你的 Agent | 按原有方式运行任务 | 保留现有框架、模型和工具 |
| Codex 中的 ATK Skills | 引导当前会话分析结果、提出并实施修改 | 用自然语言推进工作，无需手写内部操作命令 |
| 本地 ATK 工具 | 运行评测、保存证据、对比版本、管理 Git 检查点 | 每次决策都能回看依据，未采用的修改可以恢复 |

你决定评测标准和允许修改的范围。ATK 保存结果的同时，也会保留证据不足的结论，帮助你判断哪些修改值得保留、哪些仍需验证。

## 安装

需要 **本地 Codex、Python 3.11+ 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)**。

**1. 在终端安装：**

```sh
uv tool install agent-tune-kit@latest
atk install
```

**2. 在 Codex 中输入 `/plugins`，找到并启用 Agent Tune Kit。**

**3. 在 Codex 中打开你自己的 Agent 项目，输入 `$atk-init` 开始。**

下面的 `$atk-*` 都是在 **Codex 对话中**输入的 Skill 调用，不是终端命令。使用时无需下载本仓库。

如果终端找不到 `atk`，运行 `uv tool update-shell` 后打开新终端。如果 Codex 没有显示 Skills，刷新插件列表并打开新会话；可在终端运行 `atk status` 检查安装状态。

## 快速开始：完成第一次评测与改进

先选一个小目标，例如“减少客服 Agent 对退款条件的误判”。准备：

- **Agent 入口**：它在项目中如何启动，以及所需的依赖和凭证。
- **几条代表性任务**：既包含失败案例，也包含目前回答正确、希望继续保持的案例。
- **判断依据**：预期答案、业务规则，或你认可的好坏示例。

正式评测与调优需要干净的 Git 工作区，请先提交或妥善保存现有改动。评测会实际调用你的 Agent，可能消耗模型或工具额度；涉及发消息、写数据库等操作时，请准备测试环境。

下面的路径仅为示例，请替换为实际路径。**每次发送一条调用，等完成后再继续。**

### 1. 接入 Agent，准备测试任务

```text
$atk-init 我的 Agent 入口是 scripts/agent.py，请检查如何运行并完成接入。本轮只允许修改 prompts/。
```

```text
$atk-dataset 使用 data/eval.csv 中的任务，帮我确认输入、预期结果和判断标准，并保留原本正常的任务用于检查退化。
```

这一步让 Codex 弄清楚如何运行你的 Agent、哪些文件可以改、怎样判断结果。数据还没整理成文件时，也可以先提供真实任务示例，让 `$atk-dataset` 帮你整理。

### 2. 看清当前表现，找出优先解决的问题

```text
$atk-eval 先确认运行次数、超时和预算，再评测当前版本，作为修改前的对照。
```

```text
$atk-diagnose 分析失败任务，指出最值得先解决的问题，并说明证据和还不确定的地方。
```

完成后，你会得到逐条任务的判定和失败分析。问题可能来自 Prompt，也可能来自工具、数据或运行环境；先定位原因，再决定改哪里。

### 3. 尝试一次修改，验证后再决定

```text
$atk-optimize 针对刚才确认的问题，在允许的范围内准备一个修改。
```

```text
$atk-validate 对比修改前后的结果，检查目标问题是否改善、原本正常的任务是否退化。
```

```text
$atk-decide 根据验证结果决定保留、拒绝或暂缓这次修改，并解释原因。
```

正常保留修改需要通过验证，并会在你的项目中创建本地 Git 提交。拒绝或暂缓时，ATK 保留评测记录并恢复修改前的文件。它不会自动 push、发布或部署。

需要继续处理其他问题时，重复第 3 步。准备结束时，再核对所有修改合在一起的效果：

```text
$atk-validate 执行本轮最终验证，对比累计修改与本轮最初版本。
```

```text
$atk-decide 根据最终验证结果结束本轮，总结采用的修改、效果和遗留问题。
```

## 只有运行结果？也可以开始

如果已有 CSV、JSON、JSONL 批量结果，或 Langfuse 导出，可以直接分析。仅导入分析不要求配置 Agent 运行命令，也不需要 Git。

在 Codex 中依次发送：

```text
$atk-init 本次只分析已有结果，不运行 Agent。
```

```text
$atk-eval 导入 data/traces.json，确认字段含义、脱敏规则和判断标准，再评估这些结果。
```

```text
$atk-diagnose 总结主要失败原因、对应证据，以及还需要补充的信息。
```

```text
$atk-decide 保存分析结果，结束本轮，不采用修改。
```

之后想验证改进效果，可以补充 Agent 运行配置和 Git 基线，继续使用已有证据。导入格式与映射方式见[使用指南](docs/vnext-usage-guide.md)。

## 如何查看和继续工作

结果保存在**你的 Agent 项目**的 `.atk/` 目录中。你可以直接让 Codex 帮你阅读：

```text
请总结本轮结果：哪些任务失败，修改改善了什么，有没有退化？给出证据文件链接，并生成本地 HTML 评测报告。
```

ATK 会保留任务、实际输出、判定明细、修改和决策记录。需要中途停止时，让 Codex 暂停并记录进度；恢复时让它先检查当前项目状态。

| 想做的事 | 使用的 Skill |
| --- | --- |
| 接入项目 | `$atk-init` |
| 准备或补充测试任务 | `$atk-dataset` |
| 运行评测、导入结果或重新判定 | `$atk-eval` |
| 调查失败原因 | `$atk-diagnose` |
| 尝试修改 | `$atk-optimize` |
| 检查修改效果 | `$atk-validate` |
| 保留、拒绝、暂缓、回退修改或结束本轮 | `$atk-decide` |

## 常见问题

**没有标准答案，能用吗？**

可以先分析。能够独立核查的要求可以评测；缺少可靠依据的部分会保留为未知。Agent 自己的原回答不能直接当作正确答案。

**“本地插件”是否意味着完全离线？**

评测记录和 Git 检查点保存在本地；分析使用当前 Codex 会话，运行 Agent 也可能调用你配置的外部模型或服务。请按这些服务的数据使用要求处理输入材料。

**如何升级或排查安装问题？**

再次运行安装部分的两条命令，即可更新 CLI 和 Skills。`atk install` 默认只显示简要结果；需要诊断时使用 `atk install --verbose`。覆盖安装前会备份旧文件，检查失败时会显示可用的恢复命令。

**以前用过 0.x，能直接继续吗？**

1.0.0 不会自动迁移旧 `.atk` 数据。发现旧目录时初始化会停止，请先备份并决定如何保留旧数据，或在干净的目标工程开始。不要直接覆盖旧目录。

**验证通过，是否代表线上效果一定变好？**

验证说明本次任务与判断标准下的结果。当前真实多任务收益、有效修改的采用提交和外部组件修复闭环仍待完整验收，详见[实现与验收记录](docs/vnext-implementation-report.md)。请从自己项目的小规模对照开始。
